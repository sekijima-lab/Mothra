# Runtime/security migration validation (2026-10-03)

Python 3.9 -> 3.12.15, TensorFlow 2.9.1 -> 2.21.0, Keras 2.9.0 -> 3.15.1,
NumPy 1.22.4 -> 2.5.3 and RDKit 2022.03.4 -> 2026.03.6. `requirements.txt`
contains 49 resolved runtime packages; unused historical environment pins,
duplicate tensorflow-gpu and the deprecated sklearn alias are removed.
Scikit-learn pickle inference is replaced by numeric-only ExtraTrees traversal;
PyGMO hypervolume is replaced by moocore 0.3.2.

## Security rationale

The OSV query snapshot in `runtime_validation/osv-snapshot.json` matches known
advisories for 21 of the original 89 package pins, including TensorFlow/Keras,
Requests/urllib3, protobuf, Pillow, certifi and idna. None of the 49 exact new
runtime pins matches an advisory in that snapshot. This is a dependency
snapshot, not proof that the application has no vulnerabilities. Package
removal is distinguished from upgrading retained dependencies.

TLS/IDNA behavior and trust-root removals are covered by
[TRUST_VALIDATION.md](TRUST_VALIDATION.md). That document's original Python 3.9
isolation experiment is retained as historical evidence; the same six checks
also pass with the final Python 3.12 runtime and modern HTTP/auth packages.

## Baseline and frozen criteria

The independent baseline uses Python 3.9.25, tensorflow-macos 2.9.1 / Keras
2.9.0, NumPy 1.22.4 and RDKit 2022.03.4, on macOS arm64 CPU. h5py 3.7.0 replaces
3.6.0 because a matching arm64 wheel was unavailable. This is not an exact
historical Linux/CUDA reconstruction. All environments used separate prefixes;
existing research environments were not modified.

`runtime_validation/criteria.json` was recorded before comparing results and
was not loosened. The standard modern mode initially exceeded the maximum
probability and gradient criteria. Identical-state primitive probes showed
identical matrix products but changed Eigen sigmoid/tanh arithmetic. Restoring
those activations resolved the model-level difference. Failed initial results
are retained alongside the final comparison.

## Final default-mode results

One CPU thread; original weights; dropout disabled for deterministic numerical
checks. `runtime_validation/compatible-comparison.json` records the metrics:

- All nine initial weight tensors, 64-token vocabulary and encoded inputs match.
- 256 molecules x 81 positions x 64 probabilities: max difference 5.96e-8
  (limit 1e-5); mean difference 2.01e-10 (limit 1e-6); all argmax tokens match.
- Loss matches. Maximum gradient difference 6.29e-9 (limit 1e-5).
- One Adam update: maximum weight difference 4.77e-7 (limit 1e-4).
- 2,048 molecular fingerprints, toxicity probabilities and `<0.7` decisions
  match exactly. QED differs by at most 1.11e-16; SA scores match.
- Nine fixed-seed expansion/generation cases match exactly.
- 63 hypervolume fixtures differ by at most 7.11e-15; candidate rankings match.
- A 32-molecule filter/docking fixture accepts the same seven molecules and
  produces identical scores. Vina/Open Babel subprocesses are mocked.

All 17 regression/security tests pass in a newly constructed final environment;
`uv pip check` passes for its 56 runtime/test packages. Tests cover both modes,
archive roundtrips, explicit mode overrides with preserved weights, activation
extremes/gradients, rejection of an unapproved legacy layer, sparse-gradient
aggregation, pickle-free toxicity, two-process joblib inference and local TLS.

Both modes complete one epoch on 64 molecules, with TensorBoard enabled, then
reload the saved archive and complete epoch two. Separate scratch configs,
models and log directories are used. This verifies operational training and
weight-based continuation, not equality of random initialization, dropout or
all-data training trajectories.

`runtime_reference.npz` contains the first 32 molecules' inputs/probabilities
from the independent historical run, not predictions regenerated by the new
implementation. `runtime_validation/reference-provenance.json` records source
and fixture hashes. The bundled legacy model weights are unchanged.

## Reproduce the larger comparison

Use distinct legacy/current environments and separate baseline/candidate
outputs; do not run the old dependencies in an existing research environment.
From the repository root:

```sh
# OLD_REPO is a checkout/archive of commit dbc53b9956bfbbcfe8d55a97330d03a2a62fd28f.
OLD_PYTHON tests/runtime_validation/benchmark.py OLD_REPO /tmp/mothra-baseline
.venv/bin/python tests/runtime_validation/benchmark.py "$PWD" /tmp/mothra-current
.venv/bin/python tests/runtime_validation/compare.py /tmp/mothra-baseline /tmp/mothra-current /tmp/mothra-comparison.json
# Retain the standard-mode result as a separate output; it is not the baseline.
.venv/bin/python tests/runtime_validation/benchmark.py "$PWD" /tmp/mothra-standard --no-old-compatible
```

## Limits

The numerical default reproduces the tested historical CPU float32 path. It
uses float64 intermediates for legacy multiply-add rounding and analytic
activation gradients. The 100,001-point diagnostic grid matched historical
sigmoid completely; tanh differed at one scalar-tail point (2.38e-7), while
vectorized grid elements matched. It does not promise bitwise equivalence for
all shapes, extreme values, CPUs, GPUs, training seeds or platforms.

GPU/CUDA, full-data training, complete tree-search optimization and real docking
were not run. Docker base manifest/tag/digest were verified, but its build was
not run because the daemon was unavailable; changed Debian docking binaries
can affect results. The separate viewer container is not covered. SA scoring
still uses the bundled trusted fragment-score pickle; do not substitute an
untrusted file. Keras safe mode is used, but model archives should remain trusted.

## CI publishing limitation

The current GitHub OAuth token lacks the `workflow` scope. GitHub rejected
publishing `.github/workflows/runtime.yml`. The complete read-only, SHA-pinned
workflow is retained as `runtime_validation/runtime-workflow.example.yml` for
review/install with suitable credentials. No CI run is claimed; the 17-test
result above is from the isolated local environment.
